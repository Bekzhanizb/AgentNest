# AgentNest — краткий обзор

**Статус: Pre-alpha, технический каркас.** Есть окно Electron с React-интерфейсом,
навигацией Office / Agents / Tasks / Settings, состояниями загрузки/ошибки и реальными
сведениями о версии приложения. Неработающие возможности помечены Coming soon.
Среды выполнения агентов, AI-интеграций, адаптеров баз данных и релизов пока нет.

AgentNest задуман как локальная среда создания и запуска AI-агентов. Пользователь
задаёт инструкции, выбирает провайдера и модель, разрешает конкретные инструменты,
устанавливает ограничения и изучает результат запуска. Пиксельное представление
может позже отображать реальные события, но основу продукта составляют определения
агентов и их выполнение.

## Первый сценарий и границы

Один агент читает Markdown-заметки из явно выбранной локальной папки и составляет
сводку со ссылками на источники для проверки человеком. Пользователь сохраняет
определение агента, редактирует его и может повторить запуск. Экспорт результата
требует явного действия пользователя. Этот сценарий ещё не реализован.

Предложение для MVP: один локальный пользователь, один активный запуск, один
проверенный адаптер локального провайдера и SQLite для определений и истории.
В ADR предложен Ollama; подключение ещё не создано. Дополнительные провайдеры и
пиксельный вид относятся к следующим этапам. PostgreSQL рассматривается для
возможного командного режима, MySQL отложен до подтверждения спроса. Поддержки
этих баз данных пока нет.

В MVP не входят мультиагентная оркестрация, shell-инструменты, автономная
публикация, удалённый доступ и командная работа. Работающий запуск через реального
провайдера обязателен: макет интерфейса или фиктивный ответ не подтверждают готовность.

Используются Node.js 24.19.0 и npm 11.9.0, npm workspaces и один корневой lock-файл.
Команды из корня репозитория, в том числе в PowerShell:

```powershell
npm ci
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
npm run dev
```

`dev` запускает Vite и Electron; `npm start` открывает собранные локальные ресурсы.
Сборка пока не создаёт установщик. Smoke-тест открывает настоящее окно и требует
дисплея; отдельный браузер Playwright скачивать не нужно. Windows — основной target
CI с PowerShell; факт успешной проверки фиксируется в PR. macOS, ARM и WSL GUI не
проверены. Подробнее — в документе о разработке.
